# 课题统一样式与独立 panel

先按数据结构与表达目的选图，再使用课题统一样式。色卡只定义颜色；panel 是一个可独立使用的科研图；组图是在明确叙事关系之后组织多个 panel。参考海报的拼图形式不自动成为论文图的默认结构。

## 一份课题配置

每个课题使用一个 `project_theme.json`，集中指定：色卡、全部身份到色块编号的映射、正负/中性/强调角色、连续数值色图、字体、字号层级、线宽。每次渲染保留该文件与其 SHA256，读取同一文件的所有图保持一致。当前图库 C06＋Arial 是审美预览方案，不冒充用户已为任何真实课题选定的方案。

`group_slots` 是整个课题固定的身份字典。图中只出现部分组，或数据行顺序改变，都不能重新分配颜色。颜色容量不足时减少颜色编码、分面或选择另一卡；不能循环复用并假装各类别可区分。若多个标签确实代表同一身份，可在明确登记的别名下共用槽位。

类别卡 C01–C13 用于组别；C14 为顺序数值、C15 为分歧数值。一个课题的基底卡必须适合分类。连续变量用配置中独立登记的 `continuous.sequential` 或 `continuous.diverging`，共同尺度由该指标的数据语义决定。由类别卡设计的连续扩展必须标明独立设计，不能声称作者原卡本来是渐变。图中同一种数值保持色限、中心与方向一致；不同量纲不强迫共用数值范围。

## 字体集中管理

`font_family` 与 `design` 中的 label_pt、tick_pt、title_pt、note_pt 控制同一课题的字体与字号层级。字号针对最终物理尺寸，不按海报标题大小照搬。点大小若编码数值面积，则不当成普通装饰统一放大。颜色变化、字体变化和线宽变化均不得改变数据坐标、矩阵顺序、阈值、效应、区间与统计标签。

现有字体覆盖检查会解析已安装字体；中文需要覆盖字符的字体。若发生替代，应报告实际字体并全课题采用同一明确配置。当前预览为英语轴标签的 Arial。结构渲染图若含原生标签，也读取同一字体与角色色；没有适配原生字体的后端须明确限制，不能声称批量替换已经验证。

## 单图与批量出图

`project_theme.render_panel` 读取一个 panel 表与明确 panel_spec；`plot_palette_panel` 为单图底层入口。各图型的数据和图例规则在 panel-patterns.json，43 个示例覆盖 21 种 panel 结构，重复图型来自不同参考中的应用示例，不能报成 43 种新算法。

`render_project_panels.py --manifest MANIFEST.json --theme project_theme.json --output NEW_DIRECTORY` 用同一主题重绘整份 manifest。manifest 每个项目登记 id、input、style、meta 和数值列；所有输入路径均限定在 manifest 所在目录。命令只读取提供的数据，不生成数据、不运行统计分析。输出为独立 PDF/SVG/300dpi PNG、完整表、参数与回执，旧结果保留。

要统一换色卡与字体，使用 `set_project_theme.py --from-theme project_theme.json --card card_03 --font "Times New Roman" --output project_theme_v2.json`，再重绘同一 manifest 到新目录。此操作保留身份槽位；新卡容量不够会拒绝。定制的连续映射或角色色若需沿用，必须在新主题中明确登记，不将其错误归属于新色卡。

15套卡均可通过编号查看：`set_project_theme.py --list-cards`。例如 `--card C06 --sequential-card C14 --diverging-card C15` 同时明确类别、顺序和正负数值角色。仅改变字体、保持同一基底卡时，原角色色和连续色阶保留。C14/C15按数值语义选择，不强行充当无序类别色。

现有 R/Python 低层函数保留兼容。新课题默认通过主题入口。`render_with_theme` 适配明确 palette/stack_palette 参数及 reference 语义色图；旧后端内部未知颜色的自动转换尚未全面覆盖，应补明确适配或提供主题参数，不能根据像素猜组别。R 可以读取同一 JSON 的分组字典和字体，但新增 panel 未提供 R 实现；不要声称已完成全后端自动替换。

## 什么时候组图

多个 panel 回答同一问题、分享比较对象或提供互补证据时再组合。每个 panel 保留原始数据和独立导出；组图仅安排位置、panel 字母与共同图例。参考 R03/R04/R11/R14/R15/R22/R24 是已复现的组合结构，可作为排版借鉴。数据类型不匹配时不用该组合，不为形式高级增补没有数据支撑的面板。

科研出图验收：图型与数据形状相容；读者能看懂位置/面积/颜色代表什么；单位、区间、方向和图例明确；统一替换不改数值；最终尺寸不遮挡。来源与统计检查针对正式绘图任务，不是浏览图型目录时先要求用户提交某个数据文件。

完整图库的36个组合均保存于 `combination-recipes.json`。`compose_catalog_examples.py --gallery GALLERY_DIRECTORY --ids K07 K33 --output NEW_DIRECTORY` 从经过哈希核对的独立panel重建；`--all` 重建全部36个。旧组合22个辅助panel另有 `render_saved_components.py` 固定适配器及公开数据文件；它们作为组合组件保留，不重复计为新增通用方法。更换主题后先重绘组件，再用 `compose_bundles` 配置新组件前缀，检查同一主题哈希和字体。

## 内容与图例互不遮挡

独立panel图例默认在绘图区外。气泡图类别/大小图例分别预留高度，矩阵色标、层次树、标题和行标签分开安排。堆积柱或谱线不能仅靠loc=best认定安全。panel_layout_audit.py检查图例越界和覆盖数据区域；实际导出还检查所有文本与色标。更换字体后重新检查，必要时扩大画布、换行或分面；不删除类别、隐藏点或去掉区间来消除遮挡。组合图只在语义和尺度一致时共享图例。
