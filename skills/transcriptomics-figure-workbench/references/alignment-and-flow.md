# 排版、共轴与流线契约

排版方向分三层：`page_layout`调整完整画布，保留原有物理绘图区和字体大小；`arrangement`调整独立panel的横纵排列；流线的`orientation`决定流从左到右或从上到下。改变画布不等于将所有图的量值轴转向。需要交换数据坐标时使用该绘图器明确声明的transpose/horizontal模式。

## 矩阵与组别轨道

矩阵、分组色条、数量轨道和层次树必须按同一套实际ID绑定。禁止按行数相等直接zip。重复ID、未知ID、缺少身份、别名不完整都报错。对连续重复组别显示各段而不是跨不连续段画一个组标题。

`indexed_alignment.bind_index_axes`绑定轨道与主轴的物理像素跨度；在字体替换、画布改变和导出之后再次检查每个单元中心。活动矩阵上方柱图及第二量值线轴共用完整列跨度；树的叶顺序必须与矩阵一致。指定新矩阵顺序不能保留旧树叶位置。

## 独立panel之间的真实共轴

`compose_panels`首先保存完整来源的矢量内容和图例。普通横纵排版让完整panel的顶部或左缘一致，不自动认定它们有相同数据轴。

有共同坐标的panel可在布局JSON中明确指定：

```json
{
  "align_data": [{
    "dimension": "x",
    "coordinate_definition": "Same frozen position coordinates and bp units",
    "panels": [{"id": "1", "axis": 0}, {"id": "2", "axis": 0}]
  }]
}
```

索引轴还应为每个成员提供相同的`keys`列表，记录实际ID与顺序。来源需要新版导出的`layout_geometry`、完整画布尺寸以及一致的轴范围/尺度。不同坐标、倒序、不同单位和未知几何不能硬对齐。绘图器计算各来源的数据区域和留白，以共同的数据跨度排列，保留各panel同比例缩放，全部标签/图例仍留在自己的单元内。空间不够或约束冲突就报错；不拉伸图片。

## 加权流线与成员关系

`plot_alluvial`接收完整path_id、非负weight和至少两个阶段列。阶段数不再写死为五个。每条路径在每次连接中的源/目标带宽都等于它的输入weight；节点带宽等于所有相应路径之和，所有阶段共用尺度。数量与节点间距分别记录，不能用加入间隙的全轴长度冒充总量。

零权重保留在输入和几何账本中，不绘制最小宽度；全零、无穷、负值、重复路径、未知类别/顺序、精度无法表达的极端权重都拒绝。给定stage_orders及path_order可固定顺序；默认顺序明确依赖首次出现。等宽的成员曲线与加权流图保留不同含义，不能互相冒称。

非定向加权弦图不能同时把A→B和B→A当两份独立边；反向重复必须在上游按明确语义处理。

## 导出时的图例与字体

真实图例进入独立外侧区域；画布根据实际文字范围扩展，不缩小字号或隐藏标签。合成说明使用专用上下条带，不覆盖科研标题。页面扩展和图例搬移都检查输入、坐标、点面积、数值数组、参考范围与尺度不变。

3D面和点以底层XYZ、视角和量值检查；箭头以端点/曲率检查，向量场以原始X/Y/U/V检查。屏幕投影和箭头尖端的像素舍入不作为科学数值变化。

检查仍有边界：自动字体/边界检查不能判定所有文字是否好读，稠密网络节点标签和极长段落需要目标尺寸的人工检查。历史R与原生结构后端不自动获得这些Python规则。
